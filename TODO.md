# AudioFlip delivery checklist

- [x] **Local audio editing loop:** Visitors can try a short original locally generated demo, choose or drop a local file, with WAV and MP3 supported first and other formats accepted only after successful decoding. Files above 20 MB are rejected before expensive work; decoded sources over 60 seconds are rejected; unsupported inputs show a helpful error. Audio remains on the device: no server upload, retained raw audio, auth token, identifying-data storage, or analytics. Replacing/clearing clips releases URLs and audio resources.

- [x] **Truthful effects, preview, and export:** The editor displays the file name/duration, Original comparison, trim start/end controls, effect cards, effect amounts, processing state, final duration/format, a rendered-result preview, and a real downloadable 16-bit PCM WAV. Trim is validated (`end > start`) and occurs before rate conversion. Slowed + reverb defaults to 0.80x with 0.65–1.00x and 20% wet with 0–40%; Sped up defaults to 1.25x with 1.00–1.50x dry; Nightcore-style defaults to 1.35x with 1.10–1.60x and modest brightness; Bass boost defaults to +6 dB at about 120 Hz with 0–12 dB. Playback-rate changes are explained as coupled pitch/duration changes. Preview and export use the same settings; new playback stops prior playback; the browser gesture state is explained; reverb tails are rendered; samples are peak-guarded and finite before PCM encoding; silent, mono/stereo, short, repeated-render, and invalid values are handled. Downloads are never original-file fallbacks or fake extensions.

- [x] **Accessible mobile product and honest information:** The page has a dark-charcoal, violet/lime, high-contrast, one-column mobile layout with large touch targets, visible focus, no horizontal overflow, a clear hero and demo/upload calls to action. Keyboard and touch users can upload, play, trim, set presets, reset without losing the source, render, and download with disabled/loading/error states. It explains import into an external video editor, platform rights/format rules, and includes the exact rights reminder. Below the editor are three steps, use cases, privacy notes, and pre-launch pricing: Free includes the current single-clip/WAV editor; Creator is proposed at $4.99/month and says coming soon, explaining future presets/batch/vertical export without payment, email, account, paywall, or fake proof. Vertical video is explicitly future-only.

- [x] **Source, documentation, and evidence:** TypeScript build/type checks and focused deterministic coverage for WAV header/length, trim validation, rate-duration math, and amplitude limits pass. The real original demo produces meaningfully distinct outputs for all four presets. Empty upload, invalid file, oversized file, mono, very short clip, silence, repeated upload/render, invalid trim, and processing failure paths are exercised where feasible. Desktop and narrow-mobile renderings are reviewed. README documents install/build/run commands, support/format limits, unverified browser/audio surfaces, missing features, the real TypeScript-only DSP state (no Rust/WASM claim), future Rust replacement boundary, proposed secure billing architecture, and next-build priorities. No public release or payment setup occurs.


## Phase 2 — core hardening (Rust/WASM deferred)

- [x] **Accessible proposed-Creator dialog:** Opening Creator plan coming soon moves focus into the dialog; Tab and Shift+Tab stay within it; Escape, close control, and deliberate backdrop clicks close it; closing restores focus to the trigger; background controls cannot be interacted with while it is open; title association, narrow-screen readability, and sensible scroll behavior remain intact. A compact keyboard regression test covers focus entry, Tab loop, Escape, and restored trigger focus without adding a UI library.

- [x] **Clip lifecycle and truthful comparison UI:** Reset restores neutral trim/settings while retaining the loaded source. A separate Clear clip action invalidates pending work, stops active playback/timers, revokes the rendered URL, drops source/result references, resets trim/settings/status, and returns safely to the empty state; repeated clear/reset and unmount cleanup are safe without claiming forced garbage collection. The decorative source bars are replaced with a clearly labeled playback-progress indicator rather than an implied analyzed waveform. Original comparison states that its re-encoded WAV may receive peak protection and is neither bit-identical nor loudness-matched.

- [x] **Bounded, recoverable audio render boundary:** Render/decode paths reject empty/corrupt/oversize files at both UI and decoder boundaries and reject invalid source metadata, effect IDs/settings, non-finite values, invalid trim/rates, and unsafe offline/WAV allocations. Trim occurs before rate conversion, rendered duration includes the eligible reverb tail, mono remains mono, non-mono sources render to stereo through the browser graph, shared peak gain preserves channel balance, and PCM samples are finite/bounded. A late decode/render/playback completion cannot overwrite a newer source, reset, clear, or unmounted component. Busy/error states remain recoverable and source audio remains local.

- [x] **Focused evidence and documentation:** Deterministic tests cover new validation/allocation/sample/WAV cases and modal keyboard behavior. Private browser validation covers demo/upload, effects, trim/duration, processed preview/download, invalidation, clear/reset, modal keyboard operation, and narrow layouts where observable. README/TODO/roadmap material accurately state that Rust/WASM is not shipped and record browser/device/listening limits without promising unsupported compatibility.
